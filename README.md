# Курсовая по ООП · вариант 11

База данных клиентов банка. Текущий этап включает собственный контейнер с итераторами, модель клиента и базовые операции базы с проверкой уникальности.

## Запуск

Из корня проекта в PowerShell с установленным GCC:

```powershell
New-Item -ItemType Directory -Force build | Out-Null
g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp Client.cpp ClientDatabase.cpp Date.cpp -o build/coursework.exe
.\build\coursework.exe
```

Программа добавляет три записи в контейнер, выводит их через итератор, сортирует по ID и удаляет запись с индексом 1. Затем показывает, как база принимает первую запись и отклоняет её повторное добавление.

| Этап             | Порядок ID | Размер | Ёмкость |
| ---------------- | ---------- | -----: | ------: |
| После добавления | 30, 10, 20 |      3 |       4 |
| После сортировки | 10, 20, 30 |      3 |       4 |
| После удаления   | 10, 30     |      2 |       4 |

## Структура проекта

Для курсовой достаточно сохранить плоскую структуру репозитория. Разделение идёт по файлам и их зависимостям.

| Файлы | Ответственность |
| --- | --- |
| `Date.h/.cpp` | Календарная дата. Проверка, сравнение и преобразование в строку |
| `Client.h/.cpp` | Одна запись о клиенте. ID, ФИО, дата рождения, телефон, номер счёта, тип клиента, VIP-статус, баланс и дата открытия счёта |
| `Vector.h` | Хранение элементов, обход, копирование и сортировка. Реализация шаблона доступна через заголовок |
| `ClientDatabase.h/.cpp` | Владеет `Vector<Client>`. Добавляет и редактирует записи, проверяет уникальность и даёт доступ для чтения. Сюда же будут добавлены удаление, объединение, поиск и сортировка базы |
| `ClientFile.h/.cpp` | Преобразует базу в текстовый файл и обратно. Сообщает об ошибках открытия, чтения, записи и формата |
| `MainWindow.h/.cpp/.ui` | Таблица клиентов, команды главного и контекстного меню, панель инструментов, строка состояния, подсказки и окно «About» |
| `ClientDialog.h/.cpp/.ui` | Одна форма для ввода и редактирования клиента |
| `main.cpp` и будущий `coursework.pro` | Сейчас `main.cpp` запускает демонстрацию. В Qt-версии точка входа создаст `QApplication` и откроет главное окно, а `.pro` опишет сборку Qt 5 |

- **Операции базы.** Пустой `ClientDatabase` представляет новую базу. Поиск можно начать с подстроки в ФИО и точного номера счёта. Редактирование и удаление удобно привязать к ID. После сортировки индекс строки может поменяться, а ID сохраняется.
- **Объединение.** Предлагаемая политика для двух независимых баз — выдавать импортируемым записям новые локальные ID. Номер счёта использовать для обнаружения совпадений, если у каждого клиента один уникальный счёт. При совпадении сообщать о конфликте до изменения базы.
- **Хранение.** Достаточно текстового файла UTF-8 с одной записью на строку и полями, разделёнными табуляцией. Для такого формата нужно запретить табуляцию и переносы внутри полей. Открытие файла сначала собирает временную базу, после успешного чтения она заменяет текущую.
- **Интерфейс.** Для небольшого числа записей подойдёт `QTableWidget`. Команды меню и панели инструментов могут использовать одни и те же `QAction`. В контекстном меню удобно показать редактирование и удаление выбранного клиента. Главное окно вызывает операции базы и файлового модуля, которые остаются обычным C++.

## Ревью существующих классов

| Где | Что исправлено |
| --- | --- |
| `Client.h` | Защита `#pragma once` позволяет подключать заголовок повторно |
| Баланс клиента | Хранится в `std::int64_t` в копейках. Например, 1250 рублей 50 копеек передаются как `125050` |
| Проверка клиента | Конструктор и соответствующие сеттеры проверяют ФИО, номер счёта и порядок дат. Счёт состоит только из цифр, ведущие нули сохраняются. Ошибочные значения приводят к `std::invalid_argument` |
| Уникальность записей | `ClientDatabase::add` возвращает `false` при совпадении ID или номера счёта. `update` находит запись по её ID и возвращает `false`, если ID отсутствует или счёт уже принадлежит другой записи |
| Формат даты | `setFromString` принимает ровно `DD.MM.YYYY` с годом от 0001 до 9999. Если строка или дата некорректна, метод возвращает `false` и сохраняет прежнее значение |
| VIP-статус | `isVip` и `setVip` работают с отдельным флагом. VIP-статус можно задать любому типу клиента |
| Интерфейс `Date` | Вывод выполняет вызывающий код, используя `toString`. У класса обычный деструктор, сгенерированный компилятором |
| Строковые геттеры `Client` | `getName`, `getPhoneNumber` и `getAccountNumber` возвращают `const std::string&` |

В `Date` уже правильно учтены високосные годы, сравнение год → месяц → день и сохранение прежнего значения при ошибке `setDate`. Номера телефона и счёта в `Client` уже хранятся строками, поэтому ведущие нули сохраняются.

## Как объяснить Vector на защите

1. **Размер и ёмкость.** `size_` считает реально созданные элементы. `capacity_` показывает, на сколько элементов выделена память. Ёмкость растёт как 0 → 1 → 2 → 4 → 8. Индекс даёт доступ за O(1), добавление в конец занимает O(1) в среднем по последовательности операций. При росте конкретное добавление занимает O(n).
2. **Память и объекты.** `std::allocator` выделяет свободное место. Вызов `new` с адресом создаёт копию элемента в конкретной ячейке. Поэтому `Vector<Client>` работает с классом без конструктора по умолчанию. `erase` уничтожает бывший последний объект, `clear` уничтожает все элементы, деструктор ещё и освобождает память.
3. **Копирование и рост.** Записи сначала копируются в новый буфер. Если какая-то копия не создастся, временный контейнер уничтожит уже созданные копии. После успешной записи буферы обмениваются, и прежний буфер освобождается. Копия контейнера владеет собственной памятью.
4. **Итератор.** Внутри хранится указатель. `*` читает элемент, `->` обращается к его полям и методам, `++` и `--` перемещают указатель. `end()` обозначает границу после последнего элемента. У `const Vector` итератор даёт ссылку на константный элемент. Рост памяти делает прежние итераторы и ссылки недействительными. Удаление сдвигает последующие записи.
5. **Сортировка вставками.** Берём очередную запись, сдвигаем записи перед ней, пока они должны стоять позже, и вставляем её на освободившееся место. Порядок задаёт функция сравнения, например `first.getId() < second.getId()`. Для равных ключей функция возвращает `false`, и их исходный порядок сохраняется. Лучший случай O(n), худший O(n²), дополнительная память O(1) элементов.

`at` и `erase` проверяют индекс, `operator[]` предполагает корректный индекс. Контейнер рассчитан на копируемые элементы. Для удаления и сортировки элементы также должны поддерживать копирующее присваивание.

Для подготовки к дополнительному заданию удобно взять три записи из `main.cpp` и заменить в `byId` сравнение по ID на сравнение по дате открытия. Затем попробовать обратный порядок и проговорить, почему порядок элементов с одинаковыми датами сохраняется.
