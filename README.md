# Курсовая по ООП · вариант 11

База данных клиентов банка. Готовы собственный контейнер с итераторами, операции базы, сохранение в файл и интерактивная консоль для ручной проверки.

## Запуск

В терминале MSYS2 UCRT64 из корня проекта выполни `make run`. В PowerShell, где `g++` уже доступен, добавь каталог с `make.exe` в `PATH` текущего сеанса и запусти сборку:

```powershell
$env:Path += ';C:\msys64\usr\bin'
make run
```

`make` собирает программу в каталоге `build/`, `make run` открывает интерактивное меню, `make clean` удаляет файлы сборки.

После сборки меню можно открыть напрямую:

```powershell
.\build\coursework.exe
```

### Ручная проверка

При запуске выбери `1`, чтобы открыть существующий TSV, или `2`, чтобы создать пустую базу и вводить клиентов вручную. Затем откроется меню действий.

| Команда | Действие |
| --- | --- |
| `1` | Показать записи |
| `2` | Добавить клиента |
| `3` | Удалить по ID |
| `4` | Отсортировать по ID, ФИО или балансу и сразу показать результат |
| `5` | Отредактировать по ID |
| `6` | Найти по ФИО, счёту или ID |
| `7` | Сохранить базу в TSV |
| `8` | Объединить с базой из TSV |
| `9` | Очистить базу |
| `0` | Выйти |

Создай базу и добавь двух клиентов с ID 30 и 10 и разными номерами счёта. Выбери `4`, затем `1` для сортировки по ID. Записи должны появиться в порядке 10, 30. Удали ID 10 командой `3` и проверь остаток через `1`. Даты вводятся как `DD.MM.YYYY`, баланс — целым числом копеек, телефон можно оставить пустым.

Чтобы проверить сохранение и загрузку, выбери команду `7` и укажи `build/clients-test.tsv`. Выйди через `0`, запусти программу снова, выбери режим `1` и введи тот же путь. На экране должна появиться оставшаяся запись.

## Структура проекта

Для курсовой достаточно сохранить плоскую структуру репозитория. Разделение идёт по файлам и их зависимостям.

| Файлы | Ответственность |

| `ClientFile.h/.cpp` | Преобразует базу в текстовый файл и обратно. Сообщает об ошибках открытия, чтения, записи и формата |
| `MainWindow.h/.cpp/.ui` | Таблица клиентов, команды главного и контекстного меню, панель инструментов, строка состояния, подсказки и окно «About» |

- **Интерфейс.** Для небольшого числа записей подойдёт `QTableWidget`. Команды меню и панели инструментов могут использовать одни и те же `QAction`. В контекстном меню удобно показать редактирование и удаление выбранного клиента. Главное окно вызывает операции базы и файлового модуля, которые остаются обычным C++.

## Операции базы

| Действие | Методы и результат |
| --- | --- |
| Создать пустую базу | Конструктор создаёт новую, `clear()` очищает существующую |
| Добавить, изменить, удалить | `add(client)`, `update(client)`, `remove(id)`. Редактирование и удаление используют ID записи |
| Просмотреть | `size()`, `at(index)` или цикл `for (const Client& client : database)` |
| Найти одну запись | `findById(id)` или `findByAccountNumber(account)` возвращают указатель на запись или `nullptr`. После изменения базы указатель лучше получить снова |
| Найти несколько записей | `findByName(part)` возвращает копии всех записей с заданной подстрокой в ФИО. Поиск учитывает регистр. Пустая подстрока выбирает все записи |
| Отсортировать | `sort(compare)` применяет сортировку вставками через `Vector::sort`. Порядок строк может поменяться, ID сохраняются |
| Объединить | `merge(other)` добавляет записи с новыми локальными ID. Нумерация продолжается с максимального ID текущей базы или с 1, если положительных ID нет. При совпадении номера счёта или исчерпании ID возвращает `false` и сохраняет текущую базу |

## Формат файла

`ClientFile::save(database, path)` и `ClientFile::load(database, path)` принимают путь к TSV-файлу. В первой строке идут `CLIENTS` и номер версии `1`, разделённые табуляцией. Далее одна строка на клиента и девять полей в следующем порядке.

1. ID.
2. ФИО.
3. Дата рождения в формате `DD.MM.YYYY`.
4. Телефон.
5. Номер счёта.
6. Тип клиента `Individual` или `Business`.
7. VIP-статус `0` или `1`.
8. Баланс целым числом копеек.
9. Дата открытия счёта в формате `DD.MM.YYYY`.

Для ФИО и телефона передаются строки UTF-8. В этих полях табуляция и переносы строк запрещены. Пустая база сохраняется как файл с одним заголовком. При ошибке методы сообщают о ней исключением. Загрузка сначала собирает и проверяет временную базу, а сохранение заменяет целевой файл после полной записи временного.

## Ревью существующих классов

| Где | Что исправлено |
| --- | --- |
| `Client.h` | Защита `#pragma once` позволяет подключать заголовок повторно |
| Баланс клиента | Хранится в `std::int64_t` в копейках. Например, 1250 рублей 50 копеек передаются как `125050` |
| Проверка клиента | Конструктор и соответствующие сеттеры проверяют ФИО, номер счёта и порядок дат. Счёт состоит только из цифр, ведущие нули сохраняются. Ошибочные значения приводят к `std::invalid_argument` |
| Уникальность записей | `ClientDatabase::add` возвращает `false` при совпадении ID или номера счёта. `update` находит запись по её ID и возвращает `false`, если ID отсутствует или счёт уже принадлежит другой записи |
| Формат даты | `setFromString` принимает ровно `DD.MM.YYYY` с годом от 0001 до 9999. Если строка или дата некорректна, метод возвращает `false` и сохраняет прежнее значение |
| VIP-статус | `isVip` и `setVip` работают с отдельным флагом. VIP-статус можно задать любому типу клиента |
| Интерфейс `Date` | Вывод выполняет вызывающий код, используя `toString`. У класса обычный деструктор, сгенерированный компилятором |
| Строковые геттеры `Client` | `getName`, `getPhoneNumber` и `getAccountNumber` возвращают `const std::string&` |

В `Date` уже правильно учтены високосные годы, сравнение год → месяц → день и сохранение прежнего значения при ошибке `setDate`. Номера телефона и счёта в `Client` уже хранятся строками, поэтому ведущие нули сохраняются.

## Как объяснить Vector на защите

1. **Размер и ёмкость.** `size_` считает реально созданные элементы. `capacity_` показывает, на сколько элементов выделена память. Ёмкость растёт как 0 → 1 → 2 → 4 → 8. Индекс даёт доступ за O(1), добавление в конец занимает O(1) в среднем по последовательности операций. При росте конкретное добавление занимает O(n).
2. **Память и объекты.** `std::allocator` выделяет свободное место. Вызов `new` с адресом создаёт копию элемента в конкретной ячейке. Поэтому `Vector<Client>` работает с классом без конструктора по умолчанию. `erase` уничтожает бывший последний объект, `clear` уничтожает все элементы, деструктор ещё и освобождает память.
3. **Копирование и рост.** Записи сначала копируются в новый буфер. Если какая-то копия не создастся, временный контейнер уничтожит уже созданные копии. После успешной записи `swap` обменивает указатели, размеры и ёмкости за O(1), затем прежний буфер освобождается. База также использует обмен для применения результата объединения и загрузки.
4. **Итератор.** Внутри хранится указатель. `*` читает элемент, `->` обращается к его полям и методам, `++` и `--` перемещают указатель. `end()` обозначает границу после последнего элемента. У `const Vector` итератор даёт ссылку на константный элемент. Рост памяти делает прежние итераторы и ссылки недействительными. Удаление сдвигает последующие записи.
5. **Сортировка вставками.** Берём очередную запись, сдвигаем записи перед ней, пока они должны стоять позже, и вставляем её на освободившееся место. Порядок задаёт функция сравнения, например `first.getId() < second.getId()`. Для равных ключей функция возвращает `false`, и их исходный порядок сохраняется. Лучший случай O(n), худший O(n²), дополнительная память O(1) элементов.

`at` и `erase` проверяют индекс, `operator[]` предполагает корректный индекс. Контейнер рассчитан на копируемые элементы. Для удаления и сортировки элементы также должны поддерживать копирующее присваивание.

Для подготовки к дополнительному заданию можно добавить в `sortClients` сортировку по дате открытия. Затем ввести несколько записей с одинаковыми датами и проверить, что их исходный порядок сохраняется.
